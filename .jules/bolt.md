## 2024-05-18 - Replacing sort with min+lambda is a performance trap in Python
**Learning:** In `memory.py`, eviction used `sort(key=lambda)` + `pop(0)` on capacity hit. Trying to optimize this O(N log N) operation to O(N) by replacing it with `min(key=lambda)` + `remove()` actually *decreased* performance (from 1.75s to 2.1s). This is because Timsort is highly optimized for already-sorted data (when appending 1 element), whereas `min()` must evaluate the lambda for every element every time. The true fix was using `heapq` (min-heap), dropping the time from 1.75s to 0.05s (a 35x speedup).
**Action:** When removing the smallest item from a growing collection in Python, never replace `sort` with `min(key=lambda)` hoping for O(N) gains. Always implement `__lt__` on the class and use `heapq.heappushpop()` for O(log N) operations.
